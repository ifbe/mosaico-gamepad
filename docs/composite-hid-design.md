# Composite HID 设计（讨论稿，未实现）

> 目标：一块 Mosaico 同时作为 **手柄 + 鼠标/触摸板 + 键盘**，USB 与 BLE 双链路，
> 用屏幕四个角切换「触摸面当前驱动哪个设备」。右下角暂不做。

## 1. 主机侧怎么看到设备

### 方案 A：单 HID 接口 + 多顶层集合（推荐）

一个 HID 接口，接口内放多个 *top-level collection*，每个集合用自己的 Report ID：

| Report ID | 集合 | 内容 | 主机看到 |
| --- | --- | --- | --- |
| 1 | Generic Desktop / Game Pad | 16 按键 | 游戏手柄 |
| 2 | Digitizer / Touch Screen（2 触点） | id + tip + X/Y | 触摸屏（DualSense 式触摸板） |
| 3 | Generic Desktop / Mouse | 3 按键 + 相对 X/Y + 滚轮 | 鼠标 |
| 4 | Generic Desktop / Keyboard | 修饰键 + 6 键 | 键盘 |
| 5（可选） | Consumer | 音量/播放 | 媒体键 |

- 端点：仍然只用 **1 个 IN 端点**（0x85），靠 Report ID 区分。
- ESP-Iris 补丁**不需要再改结构**，只改报告描述符长度（现在是 130，加鼠标键盘约 230）。
- 主机枚举一次就看到「键盘 + 鼠标 + 手柄 + 触摸板」，全部随时可用；能不能用取决于主机/游戏，
  不取决于我们的模式。

### 方案 B：多个 HID 接口（每个设备类一个接口）

- 每个类一个借口、一个 IN 端点（0x85…0x88），`CFG_TUD_HID=4`。
- Iris 补丁要改成「按数量生成 N 个接口」，补丁变大；故障面更大。
- 好处是某些主机/BIOS 把「独立键盘接口」当标准键盘处理；对我们这种自绘键盘没有实际收益。

**结论：选 A。** 单接口多集合是键鼠合一接收器的通行做法，改动最小。

## 2. 「模式」到底切什么

HID 描述符是**静态**的，运行中无法让主机「只看到手柄」。所以模式只切换一件事：

> **触摸面把手指事件送进哪个集合。**

- 所有集合始终在线，主机随时能用（比如游戏里同时用键盘宏和手柄）。
- ABXY 四个按键默认**永远发手柄按键**（1–4），不随模式变；这样无论如何都保留手柄能力。
- 模式只影响：触摸坐标/滑动/点击的语义。

| 角 | 模式 | 触摸面语义 |
| --- | --- | --- |
| 左上 | 鼠标（触摸板） | 相对移动光标；轻点=左键；双指=右键或滚动 |
| 右上 | 手柄 | 绝对 X/Y 两触点（Report 2）+ ABXY（Report 1） |
| 左下 | 键盘 | 屏幕下半区 QWERTY，按下发键码（Report 4） |
| 右下 | 暂不做 | — |

## 3. 屏幕布局（480×480）

```
┌──────────────────────────────┐
│ BT: advertising      ◄ 顶部状态 │  ← 状态行（已有）
│ ┌──┐                      ┌──┐ │  ← 左上/右上 模式热区（80×80）
│ └──┘                      └──┘ │
│                              │
│          当前模式区域          │  ← 手柄：ABXY 菱形；鼠标：触摸板；键盘：QWERTY
│                              │
│ ┌──┐                      ┌──┐ │  ← 左下/右下 热区（右下暂留空）
│ └──┘                      └──┘ │
│ USB: connected         ◄ 底部状态 │
└──────────────────────────────┘
```

- 热区与状态行**始终保留**，不被模式内容覆盖；键盘模式下调小键盘区域（避免遮挡）。
- 当前模式用热区高亮 + 屏幕中上方的模式名（`MODE: mouse`）提示。

## 4. 键盘模式（完整 QWERTY）

480 px 宽下 10 列 → 每键 44 px，行高 44，四行 + 空格行 ≈ 240 px，占屏幕下半区可行。

```
1 2 3 4 5 6 7 8 9 0
q w e r t y u i o p
a s d f g h j k l ⌫
⇧ z x c v b n m , ⏎
        space
```

- 每键 44×44（Apple HIG 最小 44 pt，勉强达标）；字号 14–16。
- `⇧` 是**粘滞 Shift**（按一下亮，再按一下灭），不是按住。
- 支持基础按键重复：按住同一键 >500 ms 后每 80 ms 重复一次（退格、方向键需要）。
- 只有 2 触点，所以不做多键和弦；单指输入即可。
- 触摸键盘时也画触点圆（复用现有 overlay）。

## 5. 鼠标模式（相对指针）

- 触摸板区域：整个屏幕（除四角热区与状态行）。
- 手指移动 → 光标增量；灵敏度建议 **1.0 屏像素 = 0.6~1.0 光标像素**，轻加速度曲线。
- 轻点（<200 ms、位移 <8 px）= 左键单击。
- 双指上下滑 = 滚轮（Report 3 的 wheel 字段），双指轻点 = 右键。
- 只有 2 触点，够用。

## 6. 速率与 BLE

| 链路 | 报告频率 | 说明 |
| --- | --- | --- |
| USB | 125 Hz（8 ms 循环，已有） | 鼠标需要平滑，键盘/手柄按需 |
| BLE | 建议 30–50 Hz | HOGP 是 notify，连接间隔决定上限；125 Hz 会积压 |

需要给 BLE 单独节流：鼠标位移合并（累计 delta 取整），键盘按下/松开立即发（事件型，不合并）。

## 6.5 对照 DualSense（PS5 手柄）的做法

DualSense 是一个 **USB 复合设备**，但它「多接口」的原因和我们想的不太一样：

| 接口 | 内容 |
| --- | --- |
| HID 接口（1 个） | 一个 Game Pad 顶层集合，厂商自定义的 64 字节输入报告：按键、扳机、摇杆、**触摸板坐标（报告字节 33–38）**、陀螺仪/加速度、以及输出的灯效/震动 |
| USB Audio Class | 控制接口 + 扬声器/麦克风流（UAC1），这就是「音频」那部分 |

也就是说：

- **触摸板不是独立的 HID 接口**，也没有做成 Digitizer 集合，而是塞在手柄报告的厂商字节里；
- 它之所以有多个 interface，是因为 **音频属于另一个 USB 类**，必须单独成组；
- 按键、触摸、IMU 全部在**同一个 HID 接口**里。

对我们的启示：

- 手柄 + 触摸板 + （以后）IMU → **保持同一个 HID 接口**，用我们的 Report 1/2，这和 DualSense 结构一致；
- 鼠标、键盘在 DualSense 里没有对应物（它没有键鼠能力），所以这里是我们自己的选择：
  A′ = 同一个 HID 接口里再加 Mouse/Keyboard 集合（1 个端点）；
  B′ = 每个类一个独立 HID 接口（3 个端点，S31 的 USB 有 7 个 IN 端点，够用）。

**要「更接近 DualSense」，A′ 更贴近**：一个 HID 接口承载全部输入语义，音频那种「不同类」的东西才拆接口。

## 6.6 模式 flag 的持久化设计（你提的方案）

你说的「每种模式记一个 flag，启动时读到哪个就额外启用哪种 interface」在技术上完全可行，但要点是：

**HID 描述符是开机时写给主机的，运行中改不了。** 所以流程必须是：

```
开机 → 读 NVS 里的 flag 位图 → 按启用的集合拼装报告描述符 → 启动 USB/BLE
```

这意味着 ESP-Iris 的 USB 配置描述符要**运行时构造**（现在是编译期静态数组），
补丁要升级到 v2：Iris 提供一个「应用提供的报告描述符指针 + 长度」，
Iris 在 install 时把它拼进 config descriptor。这个改动可控，但要重做一次补丁。

两个概念要分开：

| 概念 | 作用 | 何时生效 | 存哪 |
| --- | --- | --- | --- |
| 启用的类（enabled classes） | 决定描述符里有哪些集合、主机看到哪些设备 | **下次开机 / USB 重新枚举** | NVS 位图 |
| 当前模式（active mode） | 决定触摸面驱动哪个集合 | 立即 | 内存（可选存 NVS） |

改 enabled classes 需要重新枚举 USB。最省事、最可预测的做法：

- 长按某个角 1.5 s = 切换该类的 enable flag → 写 NVS → `esp_restart()`，
  设备重启后 USB/BLE 重新枚举，新描述符生效（~1 秒中断）。
- 短按 = 切换当前模式，立即生效，不动描述符。

## 6.7 最终实现（已上板验证）

### 接口与端点

| 接口 | 内容 | IN 端点 |
| --- | --- | --- |
| 0/1 | ESP-Iris console CDC | 0x81 |
| 2/3 | ESP-Iris data CDC | 0x83 |
| 4 | HID 手柄（Report 1：16 按键） | 0x85 |
| 5 | HID 鼠标（Report 2：3 键 + 相对 X/Y + 滚轮） | 0x86 |
| 6 | HID 键盘（Report 3：修饰键 + 6 键） | 0x87 |

**为什么是 3 个 HID 而不是 4 个**：S31 的 USB HS 控制器只有 IN 端点 0..7
（`ep_in_count = 8`，含 EP0），Iris 的两对 CDC 已占用 0x81/0x83，可用只剩
0x85–0x87。最初把「触摸板」做成第 4 个接口用 0x88，`epnum 8` 越界，导致
`usbd_open_edpt_pair` 失败、主机在 EP0 上 STALL、整个配置枚举不成功。
**触摸板与鼠标功能重叠**，最终去掉独立触摸板接口，触摸坐标只在内部使用
（驱动鼠标/键盘输入、屏幕画触点圆）。

### 模式与布局

四角**只切换屏幕布局**，不改变主机看到的设备：

| 角 | 布局 | 触摸去向 |
| --- | --- | --- |
| 默认 | 空白 | 无 |
| 左上 | 鼠标 | 相对指针；轻点=左键；双指=滚轮 |
| 右上 | 手柄 | ABXY → 手柄接口 |
| 左下 | 键盘 | 五行 QWERTY → 键盘接口（两指可打组合键） |
| 右下 | 终端 | 12 行日志（App / Iris / IDF），屏蔽 GSP TE 刷屏 |

常驻层：顶部 BT 状态、底部 USB 状态、四边跑马灯、触点圆、四角标记（当前布局高亮）。

### 配置（Iris RPC，服务 0x4700）

| method | 参数 | 作用 |
| --- | --- | --- |
| 1 | `{"cmd":"list"}` | 返回启用位图与当前布局 |
| 2 | `{"cmd":"enable","class":"mouse"}` | 写 NVS |
| 3 | `{"cmd":"disable","class":"mouse"}` | 写 NVS |
| 4 | `{"cmd":"layout","layout":"keyboard"}` | 立即切换布局 |
| 5 | `{"cmd":"reboot"}` | 重新枚举，应用启停 |

NVS：`gamepad/classes`，bit0 手柄、bit1 鼠标、bit2 键盘，默认 `0x7`。
`enable/disable` 需要 `reboot` 才生效（HID 描述符是开机时构建的）。

### Iris 补丁

- `0001`：USB 描述符加入 HID 接口（最早的静态版本，已被 0002 取代）
- `0002`：配置描述符运行时构建；`esp_iris_usb_set_hifaces()` 注册表；
  接口表**按值拷贝**（早期版本只存指针，导致悬垂指针、描述符内容为垃圾）

### 已知限制

- 只有 3 个 HID 类；想加第 4 类必须先腾出一个 IN 端点（例如关掉 Iris data link）
- 键盘为单层布局（无数字/符号第二层，SHIFT 只对字母生效）
- 双指手势只有滚轮；没有双指轻点=右键
